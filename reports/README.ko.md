# 실행 보고서 안내

[English](README.md) | [한국어](README.ko.md)

이 보고서는 원본 맵, Blueprint 함수, 위젯, AI Controller와 내비게이션을 실제 Unreal Engine에서 실행한 기록입니다. 명시한 테스트 상태를 구성해 특정 시나리오를 확인했습니다. 수치는 동작 검증 항목이나 표본 사건의 개수이며, 머신러닝 정확도 또는 모든 플레이 상황에 대한 검증률이 아닙니다.

[결과와 측정 범위](../docs/results.ko.md), [소스 출처](../docs/source-provenance.ko.md), [재현 명령](../docs/reproduce.ko.md)을 먼저 확인할 수 있습니다. [Blueprint 검토 자료](../inspections/README.ko.md)는 기대 결과의 근거가 되는 그래프와 Data Table을 제공합니다.

새 복원 실행 요약에는 자동화 검증 묶음 7개의 성공을 포함한 실행 결과가 있습니다. 검증 묶음 개수와 개별 검증 항목 개수는 서로 다릅니다. 소스 일치 여부, 빌드 성공, 게임 동작 검증도 각각 별도로 확인합니다. 실행 도구는 프로세스 종료 코드에 더해 보고서의 검증 결과와 자동화 실행 결과를 확인합니다.

엔진 실행은 유지보수에 사용한 PC의 네이티브 Windows Unreal Engine 5.4.4 환경에서 수행했습니다. 새 디렉터리 복원과 소스 빌드를 통해 복사한 바이너리에만 의존하지 않았음을 확인했지만, 독립된 다른 컴퓨터나 가상머신에서 인증한 것은 아닙니다. Windows와 Linux의 도구 검증은 Linux 게임 실행을 인증하지 않습니다. 빌드가 최신 상태인지 확인하는 실행 시간도 처음 전체 소스를 컴파일한 시간과 구분해야 합니다.

## 초기 동작과 수정 후 동작

| 보고서 | 결과와 해석 |

| [초기 Blueprint 검사](initial-blueprints.json) | 외부 제공 에셋의 경고를 포함한 초기 컴파일 관찰 |
| [최종 Blueprint 검사](final-blueprints.json) | 현재 에셋의 컴파일 관찰 |

| [상호작용 검증](corrected-interaction-contracts.json) | 타깃 선택 행렬, 위젯 거래, 음식 사용과 희귀 아이템 표본 추출 |
| [퀘스트 검증](corrected-quest-contracts.json) | 조건 경계와 중복 보상 방지를 포함한 복합 확인 항목 8개 |
| [퀘스트 제안 표본](corrected-quest-probability.json) | 시드 378로 조건을 충족한 Talk 호출 10,000회 중 제안 1,003회 |
| [내비게이션 검증](final-navigation-contracts.json) | 실제 이동과 네이티브 경로 상태를 관찰한 3단계 |
| [인벤토리 입력 검증](final-inventory-input-contracts.json) | 실제 E 누름과 해제 및 원래 60초 재등장을 포함한 확인 항목 6개 |

초기 보고서의 실패 상태는 비교 근거로 보존합니다. 실패 항목 8개는 중요한 일반 대사보다 새 퀘스트 확률 분기가 먼저 실행되는 경우이며, 1개는 상호작용이 열린 상태에서 귀가 의도를 설정하는 경우입니다. 테스트 상태 구성 자체가 잘못된 시도는 이 초기 기준에 포함하거나 수정 후 결과와 합산하지 않았습니다.

타깃 선택 행렬은 액터의 전방 방향을 기준으로 정한 30개 조건이며, 각도가 정확히 같은 조건은 제외합니다. 카메라 기준 타깃 선택을 측정한 결과가 아닙니다. 퀘스트와 거래 검증은 특정 경계에 도달하도록 임시 상태를 구성하며, 모든 퀘스트, NPC 행동 순서와 UI 배치를 검증했다고 해석하지 않습니다. 표본 추출은 각각 분모를 구분합니다. 조건을 충족한 Talk 호출 10,000회는 퀘스트 완료 10,000회가 아니며, 희귀 아이템 976회는 별도의 10,000회 호출 실험 결과입니다.

인벤토리 입력은 운영체제의 물리 키보드 입력이 아니라 실제 PlayerController 입력 스택과 위젯을 사용합니다. 내비게이션은 실제 월드 틱과 경로 추종으로 확인합니다. 귀가 검증은 도달 가능한 가까운 임시 귀가 지점을 사용하므로, 모든 원래 귀가 좌표에 도달할 수 있음을 인증하지 않습니다. 속도 검증은 실제 Behavior Tree 태스크 인스턴스를 읽으며, 클래스 기본값 300과 구분해 트리에 저장된 속도 150을 유지합니다.

## 미채택 최적화와 최종 부하 측정

| 근거 | 해석 |
| --- | --- |
| [조회 통합 실험 사전 계획](declined-lookup/performance-experiment-plan.json) | 후보 측정 전에 정한 채택 기준 |
| [후보 적용 기록](declined-lookup/candidate-application.json) | 검토 가능한 조회 통합 적용 근거 |
| [조회 통합 후보 판단](declined-lookup/lookup-candidate-decision.json) | 12.97435ms에서 12.45090ms로 4.03% 감소했으나 기준 5%에 미달해 미채택 |
| [초기 및 후보 원시 실행 기록](declined-lookup/) | NPC 50명에서 초기 3회와 후보 3회를 구분해 보존 |
| [최종 부하 측정 묶음](final-profile-batch.json) | NPC 5명, 20명, 50명을 각각 3회 실행한 유효한 최종 측정 9개 |
| [최종 원시 측정](profiles/) | 프레임 표본, Controller와 Brain 수, 개별 액터의 이동 및 경로 관찰 |

조회 통합 실험은 초기 소스의 같은 부하 조건에서 양쪽을 비교했습니다. 당시 활성 상태 플래그는 유효한 경로에서 걷고 있음을 증명하지 않았습니다. 후보가 채택 기준을 충족하지 못해 초기 조회 구조를 복원했습니다. 이 수치를 내비게이션 복구 후의 최종 부하 측정과 비교해 성능 향상이나 저하로 표현할 수는 없습니다.

최종 측정 9개는 모두 측정 조건을 통과했습니다. 각 실행에서 요청한 NPC 전원을 관찰했으며, AI Controller와 실행 중인 Brain 수도 확인했습니다. 이동 유효 조건은 적어도 한 명의 같은 액터에서 2차원 변위 25uu 초과와 실제 이동 중인 완전한 경로를 함께 관찰하는 것입니다. 모든 NPC가 계속 걸어야 하는 조건은 아닙니다. 해당 조건을 관찰한 액터는 NPC 5명 실행마다 5명, 20명 실행에서 15~18명, 50명 실행에서 40~41명이었습니다.

최종 실행은 실제 1280 × 720 뷰포트와 D3D12 렌더링에서 준비 10초, 측정 15초로 수행했습니다. 월드 액터 틱 구간에는 모든 액터와 구간 사이의 월드 작업이 포함됩니다. 에디터 프레임 종료 간격에는 에디터, 렌더링 대기와 관찰 비용도 포함됩니다. 이동 관찰은 액터 틱 측정 구간 밖에서 수행하지만 프레임 종료 간격에는 반영됩니다. 따라서 NPC만의 CPU 시간이나 패키징한 게임의 FPS로 해석하지 않습니다.

## 공개 기록의 보존 범위

[보고서 출처 기록](report-provenance.json)은 공개한 JSON과 원본 보고서를 연결하고 양쪽 해시를 기록합니다. 로컬 파일 경로 접두사를 가리고 JSON 서식을 통일했으며, 게임 상태 값, 수치와 표본 배열은 보존했습니다. 초기 실패 상태와 최적화 미채택 판단도 그대로 남겼습니다. 공개용으로 선별한 보고서는 무관한 작업 이력 없이 프로젝트 검토에 필요한 근거를 제공합니다.
